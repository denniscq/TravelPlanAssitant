# Design: Simplified Map 力导向布局重构

## Context

当前 `SimplifiedMap` 使用 "顺序方位角布局 + 对数距离压缩" 算法。它本质是一个 "地理坐标模拟器"，产生三个用户可见的缺陷（详见 `proposal.md`）。需要从根上替换为 "路线示意图生成器"。

约束：

- 组件 props 接口保持不变，`StepRoutePlan.tsx` 不动。
- 真实 AMap 上的 `MarkerWithPopup`、`RouteDetailMarkers`、`RouteLine` 不动（属于真实地图职责）。
- 线段长度不映射真实距离（用户明确拒绝）。
- 沿用手绘铅笔风（`pencil-*` 系列）。
- 完全相同的输入必须产生完全相同的输出（确定性）。

## Goals / Non-Goals

**Goals:**

- 用 SVG 单画布渲染节点、线段、标签，消除双坐标系统。
- 力导向布局保证节点之间不重叠、线段两端明确连接。
- 标签永不旋转，始终水平可读。
- 提供算法不变式的单元测试覆盖。

**Non-Goals:**

- 不改真实 AMap 任何组件。
- 不做多日行程合并图。
- 不导出 PNG/PDF。
- 不引入新依赖。

## Decisions

### 1. 选择力导向布局（而非网格或真实地图截图）

- **理由**：力导向最契合 "相对位置可读 + 连接清晰" 的目标。网格对密集节点空间不够；静态截图依赖外部服务且风格不一致。
- **替代方案**：
  - 网格 + TSP 路径：实现简单，但节点多时格子不够。
  - 基于 AMap 静态图：地理精确，但加载慢、风格不一致。

### 2. 把力导向算法独立为 `forceLayout.ts` 纯函数模块

- **理由**：算法复杂、需要单测验证不变式（确定性、距离排序、钉死锚点）。与 React 渲染分离便于测试。
- **替代方案**：
  - 写在组件内部 useMemo：耦合太紧，难以单测。

### 3. 三种力 + 起点终点钉死

- **弹簧力**（相邻 POI 之间）：用真实地理距离缩放理想边长，保证 "远近关系" 视觉保留。
- **排斥力**（任意两点之间）：反比平方距离，最小间距约 100 px，防止重叠。
- **向心力**（指向画布中心）：弱，避免整体飘出。
- **钉死约束**：起终点固定在画布左右 1/3，其余自由。
- **理由**：起点终点位置是用户最强的导航锚点，必须稳定可见。
- **替代方案**：
  - 不钉死，靠弹簧自然排布：用户难以一眼看到 "从哪里出发、到哪里结束"。
  - 所有节点都钉死：POI 多了没空间。

### 4. 300 轮迭代 + 步长从 8.0 冷却到 0.1

- **理由**：经验值，足以让 5-10 节点稳定收敛。
- **替代方案**：
  - 自适应步长：实现复杂，对单日 POI 数量场景收益有限。

### 5. 确定性 wobble

- **理由**：用户多次刷新页面希望看到一致的视觉，每次都重新随机会让画面 "抖动"。
- **替代方案**：
  - 运行时随机：违反确定性要求。

### 6. 标签尝试 4 方向防碰撞

- **理由**：实现简单，对单日 POI（≤10 节点）够用。
- **替代方案**：
  - 完整 R-tree 空间索引：实现成本高，对当前数据规模过度设计。

### 7. SVG 单画布

- **理由**：节点、线段、标签共享同一坐标系，从根上消除原方案的双坐标系统问题。
- **替代方案**：
  - 多层叠加：又退回到原方案的痛点。

## Risks / Trade-offs

- **[风险]** 力导向 300 轮迭代在低端设备上可能有几十 ms 卡顿。
  - **缓解**：包在 `useMemo` 里，仅当 stops/segments 引用变化时重算；规模小（≤10 节点）时即便不做优化也毫秒级。
- **[风险]** 当 POI 地理上确实很接近时（< 100 m），排斥力可能把它们推开到不自然的位置。
  - **缓解**：在理想边长上叠加最小边长下限（例如 90 px），避免 "过度推开"。
- **[风险]** 起点终点被钉死后，如果某段 POI 链天然倾向 "起点附近就结束"，布局可能把全部节点挤到起点一侧。
  - **缓解**：向心力 + 迭代步长冷却让节点群落自然向中心收敛；300 轮通常足够。
- **[风险]** 测试覆盖力导向算法的几何不变式难写（不期望具体坐标，只期望关系）。
  - **缓解**：测试断言 "确定性的字节相等"、"起点始终在左 1/3"、"任意两点的相对远近与地理远近的 Spearman 等级相关"。

## Migration Plan

无（前端纯组件重写，无运行时迁移）。代码层面：

1. 新建 `src/components/map/forceLayout.ts`，导出力导向纯函数。
2. 新建 `src/components/map/SimplifiedMap.test.ts`，单测覆盖算法不变式。
3. 重写 `src/components/map/SimplifiedMap.tsx`，消费 `forceLayout` 的结果做 SVG 渲染。
4. 不修改 `StepRoutePlan.tsx` 的调用方式（props 兼容）。
5. 手动在 dev server 上跑一次流程，截图对比原缺陷是否消失。

回滚策略：若新实现出现视觉 bug，将 `SimplifiedMap.tsx` 回退到 git HEAD 即可，调用方不受影响。
